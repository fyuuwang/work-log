# 类别表（categories.md）

> AI 摄取待办时用于：**归类父任务**（别名→规范父任务名）、**选 `type`/`source` 受控词**、**识别人名抓 `assignee`**。
> 词表没有的新值，AI 应**提议**并由用户确认后补入，不擅自创造规范值。

---

## 一、父任务别名表（alias → 规范父任务名）

AI 看到别名时归入对应规范父任务；未命中则归入 `其他`，或遇明显新项目时提议新增。

```
工作任务平台:      [工作任务平台, 工作任务, 任务平台, 周例会, 香香, 香香老师]
企微用友审批:      [企微用友审批, 企微, 用友, 用友审批, 审批, UI稿, UI设计, 胡总, 宏玉]
用友MDG:           [用友MDG, MDG, 客商, MDG配置]
设备管理:           [设备管理, 设备, 赛辉信达]
其他:              [*]   # 兜底
```

> 说明：以下人名仅用于"人名自动抓"——出现在待办文字里时写入 `assignee`，**不代表项目归属**：香香、宏玉、胡总、高佳怡。
> 注意：高佳怡只是可识别的人名，不是用友MDG 的项目别名（曾误写入，已移除）。

---

## 二、type 受控词表（待办类型）

AI 归类时从下表选**最贴切**的一个；都不贴切用 `其他`。

| 规范值 | 含义 / 典型例子 |
|--------|----------------|
| 需求 | 需求梳理、PRD、角色/权限规划 |
| 开发 | 系统开发、脚本、配置、接口 |
| 采购 | 采购立项、招标、合同、供应商管理 |
| 审批 | 用印、合同审批、流程审批 |
| 会议 | 周例会、评审会、对齐会 |
| 文档 | 改名方案、材料撰写、制度文档 |
| 沟通 | 协调、请评估、同步、找人要材料 |
| 运维 | 数据导入导出、批量处理、例行运维 |
| 其他 | 兜底 |

---

## 三、source 受控词表（待办来源）

AI 归类时从下表选一个；都不贴切用 `其他`。

| 规范值 | 含义 / 典型例子 |
|--------|----------------|
| 领导交办 | 领导安排、上级压下来的活 |

| 其他 | 兜底 |

---

## 四、扩展约定

- 新增父任务：AI 提议规范名 + 别名清单，用户确认后写入第一节。
- 新增 `type`/`source` 值：同上，确认后补入第二节/第三节。
- 本文件只增不改既有规范值（避免历史数据归类漂移）。
