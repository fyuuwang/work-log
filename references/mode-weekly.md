# 模式 C：每周工作周报（MODE=weekly）

触发：自动化 C，每天 17:20 **先判定星期**，仅周五继续；非周五自动结束（见下）。
目标：产出本周"干了什么 + 没干什么"的**两层周报**，分别存入 ③ 自阅周报 与 ④ 领导周报 两个独立文件。

## 0. 星期网关（由自动化 C 的 prompt 保证，这里再强调）

触发时先判定当前星期：
- 主：`date +%u`（本地系统时间，1=周一..7=周日，**周五=5**）。受控机器上可靠、零依赖、零延迟。
- 可选交叉校验：如担心系统时间被篡改，可 `curl --max-time 6` 调 `https://worldtimeapi.org/api/timezone/Asia/Shanghai` 解析 `day_of_week`（0=周日..6=周六，周五=5）做二次确认；**本环境该 API 常不可达，抓取失败时以本地 `date` 为准，不阻塞、不重试**。
- 判定：周五 → 继续；否则输出"今日非周五，跳过周报"并结束，**不写文件**。

> 本模式只在周五被真正执行；非周五时自动化已提前结束，不会进入本流程。

## 1. 抓取本周会话并富化上下文

- 时间窗：本周一 00:00 至周五 17:20（本地日期，UTC 换算）。
- **主源**：`sessions` 表，按 created_at/updated_at 过滤本周，读取完整元数据（含 `custom_title`、`cwd`、`project_id`、`model`）。`custom_title` 是用户手动设置的标题，比自动 title 更准确。
- **trace 回溯**：本周 `daily/YYYY-MM-DD.md` 的"大总结"节是周报主干输入。若某条日志内容模糊（如"制定XX方案"未说明具体方案内容），使用 `read_trace.py --session <session_id>` 回溯该会话的实际 trace 数据，提取用户原始提问和 AI 产出，补充具体上下文。
- **待办交叉引用**：读 `todos.json`，提取本周完成/更新的待办 `result`/`notes` 字段，与 daily 日志交叉验证，确保"没干什么"基于真实待办差距。
- **不再依赖 `conversation_search`**（持续返回 0 结果）。
- **辅助材料**：本周 `daily/YYYY-MM-DD.md` 的"大总结"节。"大总结"中的每条事项在写入时已有 trace 上下文支撑，周报可直接引用其具体内容。

## 2. ③ 自阅周报（weekly-self，大总结）

- 内容：分两大部分书写——「第一部分：本周概要」汇总各板块简要说明（每条遵循「三要素」点名规则，见下方模板）；「第二部分：Trace 回溯原始数据」按板块列出 trace 数据，供核对简要说明的准确性。末尾附"本周没干什么"。
- 落盘：`E:/OneDrive/Datas/03_中旅发展/AI_WorkPlace/work-log/weekly-self/YYYY-Www.md`（如 `2026-W28.md`）。若同周文件已存在，追加而非覆盖。

## 3. ④ 领导周报（weekly-lead，小总结，对③再压缩）

- 定位：可单独转发/归档的领导成品，与 ③ 分离存储。落盘：`E:/OneDrive/Datas/03_中旅发展/AI_WorkPlace/work-log/weekly-lead/YYYY-Www.md`（同周编号）。若已存在，追加而非覆盖。
- 文风对标用户历史周报（两段式、编号、单行单产出、供应商通用化）。
- **③→④ 提取管线**：
  1. 读 ③「第一部分：本周概要」各板块「三要素」内容。
  2. **项目名动态生成**：以 ③ 板块名为基础轻量归一（稳定映射可沿用，如"供应商/采购/合同管理"→"企微用友审批"；新板块允许新增），不硬编码固定名录。
  3. **蒸馏单行产出**：每条压成"状态词（完成/持续/正在/进行）+ 核心结果"，**去掉 trace 细节与具体供应商/合同文件名**（泛化为"供应商"等通用词）；跳过"环境与工具""个人学习"等非业务板块。
  4. **下周计划**：从 `todos.json` 的 open/waiting 项 + ③「本周没干什么」中带 due 日期的项提取，压 3~5 条，领导口吻写下一步。
  5. 领导口吻：主动态、无"我"、无过程细节、禁编造；不超出 ③ 信息范围。

```
# 2026-W28 周报（周一 ~ 周五）· 自阅

## 本周没干什么（遗留/阻塞）
- <计划未推进的事项 + 原因>
```

### ④ weekly-lead/YYYY-Www.md
```

1. <项目名，源自③板块归一>：<状态词><核心产出，单行≤25字>。

（每个业务板块一行；一行最多 2 个强相关产出，禁止分号串多个不相关事项）

## 二、下周工作计划
1. <项目名>：<下一步动作>。
2. <项目名>：<下一步动作>。

```

## 纪律

- 周报只在周五生成。
- 真实数据；"没干什么"基于待办/计划与实际的差距，不臆测。
- ③ 求全、④ 求简；④ 不得超出 ③ 信息范围。
- 简要说明「三要素」强制点名（**仅 ③**）：每个板块的概要每条都要写出涉及的具体供应商 / 系统 / 合同文件 / 智能体模块名称（适用于所有板块）。
- **④ 结构铁律**：必须含「一、本周工作总结」+「二、下周工作计划」两段；编号 `N. 项目名：` 单行单产出；供应商/合同名**通用化**（不点名具体乙方）；项目名从 ③ 板块动态生成；**无"遗留"段**。
- 每周生成后提示用户：④ 已就绪、可转发。
